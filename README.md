# Workout App — Модуль записи тренировок

[cite_start]Мобильное приложение на Swift для учёта тренировок и фитнес-прогресса[cite: 4]. [cite_start]Данный модуль позволяет пользователям быстро фиксировать выполненные упражнения, подходы, веса и длительность, чтобы эффективно отслеживать нагрузку и динамику результатов[cite: 5].

---

## 🚀 Цель проекта
[cite_start]Предоставить пользователю простой, быстрый и интуитивный инструмент для ведения журнала тренировок[cite: 7]. [cite_start]Приложение помогает планировать спортивные нагрузки, избегать перетренированности и наглядно отслеживать прогресс по дням и отдельным сессиям[cite: 7, 8].

---

## 🛠 Архитектура и Модель данных

[cite_start]Логическая модель построена на разделении ответственности между справочными данными и конкретными сессиями[cite: 58, 60]:

* [cite_start]**Workout (Тренировка):** Одна сессия в календаре[cite: 36]. [cite_start]Хранит метаданные: дату/время начала, название, тип и общий комментарий[cite: 44, 59]. [cite_start]Связь $1\rightarrow N$ с `WorkoutExercise`[cite: 36].
* [cite_start]**Exercise (Упражнение):** Элемент глобального справочника (название, целевая группа мышц)[cite: 37, 45]. [cite_start]Не содержит данных о выполнении[cite: 60, 61].
* [cite_start]**WorkoutExercise (Упражнение в тренировке):** Связующая сущность ($M\leftrightarrow N$), фиксирующая факт выполнения конкретного упражнения в рамках определенной сессии[cite: 37, 38]. [cite_start]Хранит локальный порядок (`orderIndex`) и заметки к блоку[cite: 38, 46]. [cite_start]Связь $1\rightarrow N$ с `Set`[cite: 39].
* [cite_start]**Set (Подход):** Измеримые параметры одного подхода (вес, повторения, длительность, дистанция) и его порядок (`setIndex`)[cite: 40, 47].

### Правила согласованности (MVP)
* **Индексация:** Порядок упражнений (`orderIndex`) и подходов (`setIndex`) строго контролируется. [cite_start]При удалении или изменении порядка элементов внутри блока выполняется автоматическая перенумерация без «дыр» в индексах[cite: 50, 51, 52].
* [cite_start]**Каскадное удаление:** При удалении тренировки удаляются все связанные упражнения сессии и их подходы[cite: 54]. [cite_start]При удалении `WorkoutExercise` очищаются его подходы[cite: 55].
* [cite_start]**Защита справочника:** Удаление `Exercise` из справочника заблокировано, если на него ссылаются прошлые тренировки[cite: 57].

## 📱 Основной функционал & Экраны

### 1. Главный экран (Список тренировок)
* [cite_start]Отображение истории тренировок по датам[cite: 66].
* [cite_start]Краткая сводка в строке: дата, тип, количество упражнений и длительность[cite: 67].
* [cite_start]Экран-заглушка при отсутствии записей с кнопкой быстрого старта[cite: 97, 98].

### 2. Экран создания и редактирования
* [cite_start]Формирование черновика тренировки (данные не сохраняются в постоянное хранилище до нажатия кнопки «Сохранить»)[cite: 91].
* [cite_start]Валидация перед сохранением: обязательное наличие даты и минимум одного добавленного упражнения[cite: 92].
* [cite_start]Добавление упражнений из справочника или создание новых вручную[cite: 18, 19].
* [cite_start]Динамическая валидация параметров подхода в зависимости от типа упражнения (силовое/кардио)[cite: 21, 22, 48].

### 3. Экран деталей тренировки
* [cite_start]Полный просмотр структуры выполненной сессии[cite: 76].
* [cite_start]Функция **«Повторить тренировку»**: копирование структуры (упражнений и подходов) прошлой сессии в черновик новой с возможностью правки[cite: 33, 77].

## 🧭 Пользовательские сценарии (Спецификация)

1.  [cite_start]**Новая тренировка:** Главный экран $\rightarrow$ Кнопка «Новая тренировка» $\rightarrow$ Заполнение метаданных (дата по умолчанию текущая) $\rightarrow$ Добавление упражнений и подходов $\rightarrow$ Сохранение[cite: 79, 80, 81].
2.  [cite_start]**Повтор сессии:** Просмотр деталей прошлой тренировки $\rightarrow$ Кнопка «Повторить» $\rightarrow$ Открытие предзаполненного черновика на текущую дату $\rightarrow$ Корректировка и сохранение[cite: 82, 83].
3.  [cite_start]**Редактирование/Удаление:** Детали вчерашней тренировки $\rightarrow$ Изменение параметров/весов или удаление сессии с обязательным подтверждением действия[cite: 84, 87, 102].

## 🛠 Технические требования к реализации (Swift)

* [cite_start]**UI & State Management:** Интерфейс должен автоматически обновляться при изменении данных в хранилище (использование Reactive-подхода: Combine/AsyncSequence или механизма делегатов/callbacks для соблюдения Single Source of Truth)[cite: 95].
* [cite_start]**Обработка ошибок:** В случае сбоя сохранения пользователь должен оставаться на форме с сохранением всех введенных данных, а на экран выводится уведомление (Alert/Toast)[cite: 100].
