# Workout App — Модуль записи тренировок

Мобильное приложение на Swift для учёта тренировок и фитнес-прогресса. Данный модуль позволяет пользователям быстро фиксировать выполненные упражнения, подходы, веса и длительность, чтобы эффективно отслеживать нагрузку и динамику результатов.

---

## 🚀 Цель проекта
Предоставить пользователю простой, быстрый и интуитивный инструмент для ведения журнала тренировок. Приложение помогает планировать спортивные нагрузки, избегать перетренированности и наглядно отслеживать прогресс по дням и отдельным сессиям.

---

## 🛠 Архитектура и Модель данных

Логическая модель построена на разделении ответственности между справочными данными и конкретными сессиями. MVP предполагает хранение данных локально на устройстве. Для персистентности данных используются механизмы, предоставляемые платформой.

* Workout (Тренировка): Одна сессия в календаре. Хранит метаданные: дату/время начала, название, тип и общий комментарий. Связь  с `WorkoutExercise`.
* Exercise (Упражнение): Элемент глобального справочника (название, целевая группа мышц). Не содержит данных о выполнении.
* WorkoutExercise (Упражнение в тренировке): Связующая сущность, фиксирующая факт выполнения конкретного упражнения в рамках определенной сессии. Хранит локальный порядок (`orderIndex`) и заметки к блоку. Связь с `Set`.
* Set (Подход): Измеримые параметры одного подхода (вес, повторения, длительность, дистанция) и его порядок (`setIndex`).

### Правила согласованности (MVP)
* Индексация: Порядок упражнений (`orderIndex`) и подходов (`setIndex`) строго контролируется. При удалении или изменении порядка элементов внутри блока выполняется автоматическая перенумерация без «дыр» в индексах.
* Каскадное удаление: При удалении тренировки удаляются все связанные упражнения сессии и их подходы. При удалении `WorkoutExercise` очищаются его подходы.
* Защита справочника: Удаление `Exercise` из справочника заблокировано, если на него ссылаются прошлые тренировки.

## 📱 Основной функционал & Экраны

### 1. Главный экран (Список тренировок)
* Отображение истории тренировок по датам.
* Краткая сводка в строке: дата, тип, количество упражнений и длительность.
* Экран-заглушка при отсутствии записей с кнопкой быстрого старта.

### 2. Экран создания и редактирования
* Формирование черновика тренировки (данные не сохраняются в постоянное хранилище до нажатия кнопки «Сохранить»).
* Валидация перед сохранением: обязательное наличие даты и минимум одного добавленного упражнения.
* Добавление упражнений из справочника или создание новых вручную.
* Динамическая валидация параметров подхода в зависимости от типа упражнения (силовое/кардио).

### 3. Экран деталей тренировки
* Полный просмотр структуры выполненной сессии.
* Функция «Повторить тренировку»: копирование структуры (упражнений и подходов) прошлой сессии в черновик новой с возможностью правки.

## 🧭 Пользовательские сценарии (Спецификация)

1.  Новая тренировка: Главный экран → Кнопка «Новая тренировка» → Заполнение метаданных (дата по умолчанию текущая) → Добавление упражнений и подходов → Сохранение.
2.  Повтор сессии: Просмотр деталей прошлой тренировки → Кнопка «Повторить» → Открытие предзаполненного черновика на текущую дату → Корректировка и сохранение.
3.  Редактирование/Удаление: Детали вчерашней тренировки → Изменение параметров/весов или удаление сессии с обязательным подтверждением действия.

---

## 🛠 Технические требования к реализации (Swift)

* UI & State Management: Интерфейс должен автоматически обновляться при изменении данных в хранилище (использование Reactive-подхода: Combine/AsyncSequence или механизма делегатов/callbacks для соблюдения Single Source of Truth).
* Обработка ошибок: В случае сбоя сохранения пользователь должен оставаться на форме с сохранением всех введенных данных, а на экран выводится уведомление (Alert/Toast).
